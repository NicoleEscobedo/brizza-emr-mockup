# Brizza Clinic — clickable EMR mockup

A **preview-only** interactive mockup of a fictional luxury medical aesthetics clinic in Manhattan. It uses **synthetic sample records only**. It is not a production EMR, has no live database, and must never be used with real patient data.

This repository starts from a copy of the fixed EMR concept (`reference/emr-fixed-r4.html`, sha256 `852aa311b47f2d8ca50f3181872ff382d9ec7f52967abe212b982fe63e82c9ef`, 40/40 QA checks). The working mockup is a new multi-screen program with hash routes, a theme switcher, a guided demo, visit grouping, and a concept checkout / FEFO flow.

## How to open it

From this folder:

```bash
python3 -m http.server 8765
```

Then open [http://127.0.0.1:8765/](http://127.0.0.1:8765/) in a browser. The file to open is `index.html` (the server root). Do not use a `file://` URL if you want hash routing and fonts to behave consistently.

There is no login. Refreshing the page restores the original sample data (nothing is saved).

## How to use it

- **Schedule, Worklist, Patients, Tasks, Rooming, Point of Sale, Notes, EMR, Admin** are in the left navigation. Worklist is its own Workspace tab under Schedule. Each screen has its own hash URL (for example `#/worklist/2026-11-18?theme=01`, `#/schedule/calendar/week/2026-11-16?theme=01`, `#/tasks/2026-11-18?theme=01`, `#/inventory/catalog?theme=01`, `#/availability?theme=01`, `#/rooming/2026-11-18?theme=01`).
- **Worklist** is a top-level Workspace tab. A **Demo day** link opens 2026-11-18 with a fixed demo clock at 11:25 a.m. ET so the blush next-pending row and Late tag always show. Appointments are in time order (not grouped by provider), in collapsible buckets: In progress (Checked in through Ready for checkout), Pending (Scheduled or Confirmed), Completed (Checked out), and No-show/Canceled. Headers use a ⌄/› arrow and a shaded bar; collapse state persists in localStorage. Late sits under the time so it stays visible. Appointment notes are a compact textarea (expandable). There is no separate DOB column; date of birth stays under the name. **＋ New appointment** and **＋ Admin block** live on the Schedule (calendar) header, not the Worklist. Checkout may proceed with an unpaid or partial balance after an alert; **Left without paying** checks the visit out, moves the amount due to the patient balance, adds a red unpaid-balance alert on the chart, and creates a collect-balance task. Under each patient name is a smaller `DOB - #ID` line (mm/dd/yyyy and `#BZ0001`). There is no appointment-type color legend. Clinical notes use a red asterisk for required fields, Save and Sign, addenda on signed notes, a consult-to-procedure handoff, a local face map for injectables procedure notes, a question-driven note builder with a live preview, and a Notes dashboard in the nav for pending and signed notes. Front-desk staff can confirm, review registration, change visit status, jot appointment notes, check balances, and open a simpler Invoice pop-up. Task filters (Needs confirmation, Missing forms/ID, Ready for checkout, Unpaid balance, Open quotes, Collect balance) toggle and combine, with live counts and an All reset. The Worklist status dropdown is limited to front-desk choices in flow order; clinical statuses appear as a read-only badge. A Clinical notes column links to the visit note (or a calm dash). The Reg column shows only the compact [ID][F][D] widget; Confirmed / Not confirmed, Edit, and Confirm demographics appear in the expanded registration panel (Edit still opens the demographics pop-up). Suite sits under Time. Type and Reason share one column. A Prep column after Reg shows a compact Ready / Needs prep pill with hover and click details. Left without paying is in the Checkout / Invoice modal only, not on the main row. An Open clinical notes grouping after Collect balance lists unsigned notes for that date with provider initials and Open note. The audit-log control on every Worklist row is a clipboard-with-magnifying-glass SVG. Patient Search and a smaller **＋ New Patient** pill sit in the top bar. Patient Alerts appear first at the top of the chart, above the name, header, and tabs.
- **Schedule** also has a Calendar view with Day, Week, and Month modes. Locations toggle one at a time (Manhattan | Long Island), with an optional Compare view; providers appear as side-by-side columns in Day view and as chips (All / Rossi / Costa / Hayes) that remember their selection. Clinic hours are Monday–Friday, 10:00 a.m.–6:00 p.m. ET; non-office hours are a darker gray, and booking then is allowed with a required, logged reason. Availability is always shown as a small line under the date in Day and Month views (for example `Costa, NP · Manhattan · 10–6`); the old availability hover pop-ups are removed. Appointment hover shows only patient, type, time, and status. Clicking any open time, including an occupied slot, offers a new appointment. Cards use the existing status-legend colors on the dropdown and a thin same-color left edge; consults show the reason (for example `Consult · Toxin`). Booked appointments can be dragged to a new time or provider until the visit is Completed. ＋ Appointment from the Patient chart locks that patient as a read-only chip (no search, no + Add new patient). From Schedule, ＋ New appointment and ＋ Add open the same short booking window, and + Add new patient is a separate step. The form is Type, Provider (visible, prefilled), Date, Start with End alongside (auto-filled from the type length, always after Start, 15-minute steps), Location, Reason, and Notes. Save stays disabled until required fields are filled. Both ＋ New appointment (Schedule header) and ＋ Add (calendar slot) open this booking window (patient search and + Add new patient, Start / End / Duration in sync, Location, Type, Reason, and Notes, plus an outside-hours reason only when needed). The date comes from the current screen or slot and appears in the title, not as a visible field. The booking window’s patient field defaults to the last patient opened and searches by name, #ID, or date of birth. Opening an appointment shows a header (name linking to the chart, BZ ID, DOB, alerts, status) and Patient, Appointment, and Money panels, with details editable until checkout, Reschedule, Cancel/No-show with a required reason, and a large Create invoice button. Canceled visits appear muted with a strikethrough and a Canceled badge; a Hide canceled toggle is remembered. ＋ New appointment and ＋ Admin block sit on the Schedule header; calendar slot ＋ Add remains. The Worklist/Calendar toggle is removed.
- **Patients:** IDs are `#BZ` plus four digits (for example `#BZ0001`). Dates of birth are shown and entered as mm/dd/yyyy (slashes auto-insert as you type). Phone numbers auto-format as (XXX) XXX-XXXX. Addresses use Address 1, Address 2, City, State, Zip, and Country (United States by default); entering a zip auto-fills City and State from a built-in NYC/Long Island/NJ lookup. **＋ New Patient** (next to patient search) requires first name, last name, date of birth, and phone; address and email are optional; the next `#BZ` id is assigned and audited. The chart has an Address field (changes are audited with before/after), Patient Notes (non-clinical, timestamped, with author), and Patient Alerts (for example latex allergy or prefers text) shown as a banner at the top of the chart and inside clinical note create/view, with add/remove and audit. Confirm Demographics writes the audit entry “Demographics manually confirmed,” updates the registration indicator, and shows “Last reviewed: [date/time] by [user]” under the button. The chart keeps a single audit-log control (the History icon). Edit Chart sits in the header row with the patient name. Clinical profile and treatment history are one section. The Clinical Notes tab next to Follow-up History was removed. The header puts the patient name at the top with demographics, patient number, last provider, and last and next appointment. Clinical Notes sits above Next appointment, which includes Schedule and + Appointment. A Forms tab lists HIPAA, procedure, aftercare, and marketing consents as labeled placeholders only. The former patient list is replaced by a Clinical notes list for the open patient only (date, Edit, View/Print, Open / Signed / Locked) with search, and an Add new note button (shown to clinical roles and to MD / Clinic Owner). Documents are grouped as Patient Intake, Consent, Payment (receipts, including those created from POS payments), and Quotes (every saved quote). View opens a readable window with a Print button inside it. The Notes dashboard has a date range and a Today control bound to the demo day.
- **Audit log icon:** The same clipboard-with-magnifier inline SVG is used site-wide (aria-label and title “Audit log”). Clicking it opens a compact pop-up of that record’s history (who, role, when, field before/after). The brown Workspace / Clinic sidebar stays fixed while the main column scrolls. The acting user’s name, title, and permission sit in a sticky top bar that stays visible while scrolling. The wordmark is **Brizza**, with a larger capital B.
- **Availability** (Clinic Manager or MD / Clinic Owner; others see a permission notice) holds per-provider schedule templates: weekly days, every N weeks, a color (default creamy white), a start date, an end date or no end date, and multiple location/time blocks per day. Templates can be added, edited, or deleted in memory with audit. Clinic hours remain Monday–Friday, 10:00 a.m.–6:00 p.m. ET; blocks outside those hours are shown and flagged (open question).
- **Clinical notes:** Each Acting clinical role sees only its own templates to create (Aesthetician templates for Aesthetician; Injectable templates for RN / NP Injector). Dr. Rossi (MD / Clinic Owner) can open, create, edit, and sign any note. Non-clinical roles do not see **Create Note**. Six draft templates (Injectables and Aesthetician Consult, Follow-up, and Procedure) are labeled Open question. Injectable Procedure notes include an Other treatment area (label and units, starting empty) and auto-sum face-map plus Other units into Units documented. Aesthetician procedure notes use skin-focused questions (no face map or injectable lot fields); Consent confirmed appears only on procedure notes. Generated prose uses a framing sentence and only echoes entered facts. Reviewed, no changes is left-aligned, persists on reopen, and can be locked with user and time. Sign stays disabled until required fields are filled. Signing locks the note, records signer and time, writes audit, and stores a medical-history snapshot. Opening a past note highlights history that has changed since that snapshot. Units or amount fields stay empty and are not required.

- **EMR:** A provider section after Workspace. Today's patients for the acting provider include a short snapshot (alerts, allergies, last visit) and ＋ New note (existing role-gated composer), plus that provider's pending notes. The clinic-wide Notes list stays in Workspace.
- **Admin:** The Clinic nav item is Admin (formerly Configuration). Tabs cover Team & Access, Availability, Appointment types, Appointment reasons, Inventory, and Settings. `#/inventory` redirects to `#/admin/inventory`. Old `#/configuration`, `#/availability`, `#/appointment-types`, and `#/appointment-reasons` hashes redirect. Team & Access lists the synthetic staff with role, access, and Active status; ＋ Invite user and Edit are in-memory only, with no passwords.
- **Tasks:** The former Work queue tab is renamed Tasks and shows only Follow-up tasks (`#/tasks/DATE`; `#/queue/` still works).
- **Rooming:** Status badges use the appointment-status legend colors. Each flow column scrolls internally. On a 1280×800 viewport the Patient Flow board and Suites 1–3 fit without vertical page scroll; wait timers are compact corner badges (for example 12m, gold at 15+ minutes).
- **Point of Sale:** The POS tab uses the same two-pane catalog and separate cart as the Schedule invoice modal, with search, Remove on every line, Print receipt, and Paid preselected.
